# /kr-stock-manager

한국 주식 봇 프로젝트 코드 변경 전 필수 확인 절차.

**이 스킬은 stock_alert.py 또는 프로젝트 파일을 수정하기 전에 반드시 호출한다.**

## 출력 형식

다음 항목을 텍스트로 제시하고 사용자 승인을 기다린다:

```
[변경 대상]
- 파일: <파일명>
- 위치: 라인 N~M / 함수명

[변경 내용]
- 변경 전: <현재 동작/코드 요약>
- 변경 후: <변경될 동작/코드 요약>
- 추가 줄수 예상: +N / -M

[영향 범위]
- 직접 영향: <변경되는 함수/로직>
- 간접 영향: <연결된 함수/데이터 흐름>
- 비가역 여부: 가역 / 비가역(git push 포함)

[검증 방법]
- 변경 후 확인 방법: <wc -l / py_compile / 로그 확인 등>
```

## 규칙

- 사용자가 "어 진행해" 또는 명시적 승인 확인 전까지 Edit/Write 도구 사용 금지
- git push는 파일 변경 승인과 별개 — 사용자가 명시적으로 금지하지 않으면 push 가능
- 승인 후 변경 → 무결성 검사(wc-l / tail-5 / py_compile) → 완료 보고 순서 유지

## 부분패치 금지 원칙

변경 내용을 제시하기 전에 반드시 판단:

- 이 패치로 **근본 원인이 제거**되는가? → YES: 진행 가능
- **증상만 완화**하고 근본 원인이 남는가? → 로직 전체 재설계 먼저 제시

전체 재설계 시 [변경 내용] 항목에 반드시 포함:
```
- 근본 원인: <A가 B를 하기 때문에 C가 사라진다>
- 해결 범위: <영향받는 함수 전체 목록>
- 완전 해결 여부: YES / NO(이유)
```

부분패치가 "이미 됐으니 나중에 근본 수정" 패턴은 거부한다.
